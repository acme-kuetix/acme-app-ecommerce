# acme-app-ecommerce

Kuetix e-commerce composition app — wires `acme-cart` (and the `acme-std-*` primitives it depends on) into a runnable CLI binary for store-front flows.

## Quick Start

```bash
# Run a workflow
./runner.sh run workflows/solutions/ecommerce/<file>.wsl

# Or directly
go run ./cmd/cli <workflow-path>
```

The runner script wraps `kue update` (regenerates DI/meta cache) before launching the CLI.

```bash
./runner.sh run <workflow>     # run a workflow (positional arg)
./runner.sh start [port]       # boot the API on a port (default 9997)
./runner.sh validate           # validate every workflow file
./runner.sh build              # build runtime/bin/acme-app-ecommerce
./runner.sh clean              # remove generated cache + build artifacts
```

## Commands

```bash
make build           # builds runtime/bin/acme-app-ecommerce (APP_NAME := acme-app-ecommerce)
make run             # build + run solutions/ecommerce/startup
make start           # build + run on port 9997
make validate        # ./runner.sh validate
make clean           # remove modules/{di,meta,modules.json}.go + runtime/bin
go test ./...        # metarepo go.work must be enabled
```

## Architecture

- **cmd/cli/** - CLI entry point
- **modules/** - Wires the `acme-cart` transitions into the DI container
- **workflows/** - Composed WSL workflows (typically re-exported from `acme-cart/workflows/`)
- **runtime/** - Configuration and logs

## Development

1. Add or edit WSL workflows in `workflows/`
2. Regenerate the DI/meta cache: `kue update` (or `./runner.sh run <wf>` which runs it for you)
3. Build: `make build` (or `./runner.sh build`)
4. Test: `go test ./...`

## Notes

- `modules/di.go`, `modules/meta.go`, `modules/modules.json` carry `// Code generated by kueinit. DO NOT EDIT.` — regenerate with `kue update`, never hand-edit.
